# Technical Design Document (`9_TECHNICAL_DESIGN_DOC.md`)

## 1. Document Description & Project References

This **Technical Design Document (TDD)** replaces `docs/9_CURRENT_JOB_EXECUTION_PLAN.md` and serves as the step-by-step developer implementation and unit-testing blueprint for every requirement in **Skool CRM**. Every row maps a Requirement ID from [`docs/2_PRD.md`](2_PRD.md) to concrete, layer-by-layer instructions grounded strictly in the actual repository files, classes, methods, schemas, API endpoints, and test suites.

### Standard 4-Layer Implementation Pattern (For New Developers)
Every feature in this repository follows the exact architecture in [`AGENTS.md`](../AGENTS.md) and [`docs/3_ARCHITECTURE.md`](3_ARCHITECTURE.md):
1. **Persistence & RLS (`core/models.py`, `core/migrations/`):** Subclass `TenantScopedModel`, generate a Django migration, add `ENABLE`/`FORCE ROW LEVEL SECURITY` matching `core/migrations/0020_enable_tenant_rls.py`, and document changes in [`docs/4_DATA_AND_ENV.md`](4_DATA_AND_ENV.md).
2. **Business Object & Rule Gates (`core/business_objects/`):** Put all domain validation (`BR-XX-XX` from [`docs/rule_registry.md`](rule_registry.md)) inside Business Object methods raising `BusinessRuleError` (HTTP 422), never raw mutations in routes.
3. **Schemas & HTTP Routes (`core/schemas/`, `core/api/v1/`):** Validate payloads with Ninja schemas, authenticate with `JWTAuthBearer()`, authorize with `@require_roles(...)` and `core/auth/scoping.py` (`get_student_queryset`, `verify_student_access`, `verify_application_access`, `verify_vendor_access`), filter by `tenant_id=request.tenant_id, is_deleted=False`, and return `build_response(...)` / `build_error(...)`.
4. **Frontend Wiring (`frontend/`):** Add typed calls in `frontend/app/lib/api.ts`, build API-agnostic Tier-3 widgets in `frontend/components/widgets/` composed from `ui`/`pc` primitives and `frontend/styles/tokens.css` (zero hardcoded hex/RGB colors; Header `z-40`, Backdrop `z-[60]`, Modal/Drawer `z-[70]`, Popover/Select/DatePicker/ThePuffy `z-[80]`), and assemble inside thin Tier-4 portal pages under `frontend/app/`.
