## 2. Global Definition of Done (DoD)

Every user story in this backlog must satisfy the following baseline gates before transitioning to **Done**:

1. **Tenant & Role Isolation:** All queries filter by `tenant_id=request.tenant_id` and `is_deleted=False`, enforce route-level `@require_roles(...)` and object-level guards (`verify_student_access`, `verify_application_access`, `verify_vendor_access`), and execute under active PostgreSQL RLS context (`app.current_tenant_id`).
2. **Layered Architecture:** Domain rules are enforced in `core/business_objects/`, validated via `core/schemas/`, and exposed through `core/api/v1/` returning standardized `build_response(...)` / `build_error(...)` envelopes.
3. **Design System Compliance:** All frontend work in `frontend/app/` reuses primitives from `frontend/components/ui` and `frontend/components/pc` (`data-table`, forms, modals, badges) and semantic tokens from `frontend/styles/tokens.css`. Zero hardcoded hex/RGB values or parallel UI primitives.
4. **Automated Verification:** Positive, negative (401/403/404 cross-tenant/cross-role), and business-rule violation (HTTP 422 `RULE_VIOLATION`) tests pass in `pytest` / `python manage.py test`; changed frontend files pass ESLint and `npm run build`.
5. **Documentation & Memory Log:** Schema changes update `docs/4_DATA_AND_ENV.md`, status updates reflect in `docs/6_PLAN.md`, and a dated decision entry is appended to `docs/7_MEMORY_LOG.md`.
